# Peerivo Symphony / Симфония

«Симфония» — provenance-first корпус Писания, толкований, Предания, вопросов, диспутов и межконфессиональных/межрелигиозных разборов.

## Каноническая модель

Базовый контентный путь:

`Corpus → Work → Passage`

Scripture, святоотеческие тексты, соборы, конфессиональные документы, другие религиозные традиции, статьи и медиа находятся в одном графе, но не смешиваются как один тип источника.

Базовый путь знания:

`Passage → Interpretation → Topic → Claim → Argument → Objection → Response → SourceFragment → Person → EditorialDecision`

- Verse — специализированный индекс над Passage для мест Писания.
- Interpretation — универсальное толкование/позиция с обязательным происхождением.
- Question — постоянная сущность графа, а не одноразовый поисковый запрос.
- один Question может быть связан с несколькими Passage и Topic;
- Claim хранит конкретное утверждение и его автора/традицию/источник;
- Argument, Objection и Response формируют карту диспута;
- SourceFragment указывает точный фрагмент текста, страницу или таймкод;
- EditorialDecision фиксирует редакционную/богословскую проверку;
- PopularitySignal поднимает часто задаваемые вопросы без публикации персональных поисковых логов.

## «Путь истины»

Это блок внутри Симфонии, а не отдельный продукт:

`Question/Claim → места Писания → толкования → позиции → аргументы → возражения → ответы → статус расхождения → первоисточники`

Статусы позволяют отличать обычное расхождение от различия терминов/текста и от реально неразрешённого возражения.

## Страница места Писания

1. текст, редакция и контекст;
2. параллельные места;
3. толкования с provenance;
4. самые частые вопросы;
5. «Путь истины»;
6. карта диспута;
7. точные первоисточники.

## Хранилище

Основная БД: PostgreSQL / Supabase Postgres. Полнотекстовый поиск сначала PostgreSQL FTS/trigram; pgvector — дополнительный semantic-recall слой. Отдельный search/graph engine добавляется только после измерения корпуса и нагрузки.

Полные оригиналы и тяжёлые медиа — object storage. В Postgres — нормализованные Passage/SourceFragment, связи, provenance, права, редакционные решения и поисковые индексы.

## Ingestion

Канонический pipeline:

`Submission → Intake → Classification → Extraction → Fragmentation → Linking → Review → TheologicalReview → Publication → Corrections/Versions`

Каждый импорт имеет source identity, canonical URL, rights status/evidence, checksum, parser version и адресуемый locator. FULL_TEXT разрешён только для PUBLIC_DOMAIN, LICENSED или PERMISSION_GRANTED.

«Азбука веры» зарегистрирована как приоритетный источник, но до фиксации прав работает в LINK_ONLY / metadata-only режиме.

## M1

M1 должен дать:
- каноническую схему корпуса и редакционных ролей;
- rights-gated ingestion;
- единый поиск «стих / цитата / вопрос / мне сказали, что…»;
- превращение повторяющихся вопросов в узлы графа;
- страницу стиха с «Главное по этому месту» и «Путь истины».
